# 配置 Microsoft 登录（应用 ID）

MFMCL 的「正版登录」需要一个**你自己注册的 Microsoft Entra 应用（公共客户端）ID**。

这个 ID 不是密钥，但它和发布者绑定：Minecraft 服务授权是逐个应用授予的，所以启动器不能借用别的启动器的 ID——那既是条款问题，也会在令牌交换时失败。没有 ID 时，登录按钮只会返回「此开发构建尚未配置 Microsoft 应用 ID」。

本文是从零注册到验证通过的完整流程。

---

## 0. 先确认当前状态

有两种生效方式，任选其一：

| 方式 | 适用场景 |
| --- | --- |
| **运行时填写**（推荐） | 用的是别人构建好的安装包，不想重新编译 |
| 编译时注入 `MFMCL_MICROSOFT_CLIENT_ID` | 自己构建、要分发给别人 |

### 运行时填写

打开登录窗口 →「用 Microsoft 登录」，如果这个构建还没有应用 ID，页面上会直接
出现一个输入框。填入 36 位 GUID 后保存即可，登录立刻可用。这个值存进系统凭据库
（不是 localStorage），界面上 thereafter 只显示「已配置」，不显示内容。

构建时已注入 ID 的发行版看不到这个输入框——那是开发者的事，对用户只是噪音。

---

## 1. 注册应用

1. 打开 <https://portal.azure.com>，用你的 Microsoft 账号登录。
2. 搜索并进入 **Microsoft Entra ID**（旧名 Azure Active Directory）。
3. 左侧选 **应用注册** → **新注册**。

填写：

| 字段 | 值 |
| --- | --- |
| 名称 | 任意，例如 `MFMCL`（用户会在授权页看到它） |
| 支持的账户类型 | **任何组织目录中的账户和个人 Microsoft 账户**（见下方说明） |
| 重定向 URI | 平台选 **公共客户端/本机(移动和桌面)**，值填 `http://127.0.0.1/callback` |

> **账户类型怎么选**
> 选「任何组织目录中的账户和个人 Microsoft 账户」。这是唯一能同时覆盖个人账号与
> 工作/学校账号的选项——MFMCL 用 `common` 端点登录，它接受两类租户。
>
> 只选「仅个人 Microsoft 账户」也能用，但那样只有个人账号能登录；选「仅此组织目录
> 中的账户」则相反，只有你自己租户内的账号能进。

注册完成后，概览页上的 **应用程序(客户端) ID** 就是要用的值，形如
`00000000-0000-0000-0000-000000000000`。

---

## 2. 允许回环重定向

MFMCL 不使用固定端口：它在启动登录时绑定 `127.0.0.1:0`（由系统分配空闲端口），然后把实际端口拼进回调地址，形如 `http://127.0.0.1:52341/callback`。

因此注册时必须允许**任意端口的回环地址**：

1. 在应用页左侧选 **身份验证**。
2. 「移动和桌面应用程序」区域确认已有 `http://127.0.0.1/callback`。
3. 找到 **高级设置** → **允许公共客户端流**，设为 **是**（启用）。

> 为什么第 2 步和第 3 步都要做
> - 不登记回环 URI：Entra 会在授权阶段直接拒绝这次请求。
> - 不启用公共客户端流：即使拿到授权码，令牌交换也会因为没有客户端密钥而失败。MFMCL 是公共客户端，**不带任何 secret**，这是有意设计。

不同形态的回环地址（`http://127.0.0.1:随意端口/...`、`http://[::1]:随意端口/...`）在 Entra 的回环例外规则下通常都被接受；填 `http://127.0.0.1/callback` 是最保守的做法。

> 注意：代码只接受**字面 IP**（`127.0.0.1` / `::1`）。`http://localhost/callback` 会被启动器自己拒绝，即使 Entra 允许。登记时请用 IP 形式。

---

## 3. 授权 Minecraft 服务

这一步最容易漏。ID 有效、能登录 Microsoft，**不代表能进游戏**。

1. 打开 <https://aka.ms/mcapi>（Minecraft 开发者门户，用同一账号登录）。
2. 找到 **我的应用** / **My Applications**。
3. 把刚注册的客户端 ID 提交上去，等待审批通过。

审批状态会直接决定登录结果：

| 状态 | 表现 |
| --- | --- |
| 未提交 | 登录能拿到 Microsoft 令牌，但换成 Xbox/Minecraft 令牌时被拒 |
| 待审批 | 同上 |
| 已批准 | 正常 |

> 这一步的审批由 Microsoft 人工处理，可能耗时数天。在通过之前，任何启动器（包括官方的第三方接入）都无法用这个 ID 完成正版登录。

---

## 4. 编译时注入

在仓库根目录创建 `.env`（已被 `.gitignore` 忽略，不会被提交）：

```bash
MFMCL_MICROSOFT_CLIENT_ID='你的-应用程序-客户端-ID'
```

然后构建：

```bash
npm run tauri -- build --ci --no-sign
```

`src-tauri/build.rs` 已经监听这个变量（`cargo:rerun-if-env-changed`），改过之后重新编译会自动生效。用环境变量直接构建也可以：

```bash
MFMCL_MICROSOFT_CLIENT_ID='你的-ID' npm run tauri -- build --ci --no-sign
```

验证注入是否成功——构建产物里应当出现你的 ID：

```bash
# 把 <bundle> 换成你实际的产物路径
strings target/release/mfmcl-desktop | grep -F '你的-ID'
```

有输出说明编进去了；没有输出说明变量没传到 `cargo build` 那一层（常见原因是只在 `npm` 的子进程里设了变量，或者用了一个已经存在的 `target/` 缓存而没有变更多久）。改完环境变量后可以先 `touch src-tauri/build.rs` 强制重跑构建脚本。

---

## 5. 验证

1. 启动应用，点「登录」→「用 Microsoft 登录」。
2. 默认浏览器打开 Microsoft 授权页。
3. 页面上显示的应用名应当是第 1 步填的名字（如果是别的名字，说明 ID 不是你的）。
4. 同意后浏览器跳回 `http://127.0.0.1:<端口>/callback`，显示「可以关闭此页面」之类的提示。
5. 启动器里出现你的角色名和皮肤头像。

失败时按提示定位：

| 提示 | 原因 |
| --- | --- |
| 此开发构建尚未配置 Microsoft 应用 ID | ID 没编进去，回到第 4 步 |
| `invalid_client` | 客户端 ID 打错，或应用类型不是公共客户端 |
| `redirect_uri_mismatch` | 第 2 步的回环 URI 没登记 |
| 应用未获批准 / 无 Minecraft 权限 | 第 3 步没做或还在审批 |
| 登录等待超时 | 授权页停了超过 180 秒；重试即可 |
| 无法打开系统浏览器 | 系统缺少默认浏览器关联（无桌面环境时常见） |

---

## 6. 不要做的事

- **不要用别人的 ID**。包括从其他启动器的二进制里提取的 ID。它可能短期能跑通，但违反 Minecraft 使用条款，且对方随时可以撤销，届时所有用它的构建一起失效。
- **不要试图加客户端密钥**。公共客户端 + PKCE 是桌面应用的唯一正确形态；把 secret 塞进客户端等于公开它。
- **不要把 ID 写进源码或提交 `.env`**。ID 本身不是密钥，但它标识你的发布者身份；提交进仓库会让别人误以为那是官方构建。

---

## 附：流程涉及的具体参数

如果你的注册页面字段与本文不一致，以下值可直接对照：

| 项目 | 值 |
| --- | --- |
| 授权端点 | `https://login.microsoftonline.com/common/oauth2/v2.0/authorize`（`common` 同时接受个人与组织账号） |
| 令牌端点 | 同上路径下的 `/token` |
| 作用域 | `XboxLive.signin offline_access` |
| 授权类型 | 授权码 + PKCE（`code_challenge` / `S256`） |
| 重定向 | `http://127.0.0.1:<系统分配端口>/callback` |
| 客户端类型 | 公共客户端，无 secret |
| 回环限制 | 只接受**字面 IP** 回环地址（`127.0.0.1` 或 `::1`）；`localhost` 主机名、`0.0.0.0` 与外部域名都会被拒绝 |
| 回调接收超时 | 180 秒 |

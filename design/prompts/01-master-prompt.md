## 提示词正文

你是一名兼具桌面产品、交互、视觉及设计系统能力的资深设计师。请从零独立设计一款面向中文用户的 Minecraft Java 版桌面启动器，交付真正可编辑的 Figma Design 设计文档和可点击原型。目标是让功能覆盖与使用体验达到或超越 PCL2 所代表的成熟启动器水准，但这只是产品愿景，不是经核实的对标结论。以本提示词的明确需求作为本次验收范围。

### 2. 先探索，再选择

先提出三个实质不同、都能满足任务的设计方向。每个方向给出：核心体验原则、信息组织方式、视觉语言、主流程低保真草图、初心者如何完成首次启动、扩展性及可能代价。不要只替换颜色或圆角形成三个版本。

从首次成功率、认知负担、状态清晰度、复杂功能扩展性、可读性和实现合理性出发，自选最优方向，说明为什么更适合本项目，以及放弃另外两个方向的原因。无需将所有决定退回给用户；未指定部分采用明确、可撤销的合理假设。之后统一推进选定方案，而不是混搭三套导航。

### 3. 用户原则与默认体验

主要用户是第一次使用启动器、不理解 Java、加载器和目录隔离的玩家；同时支持经常管理模组和整合包的熟练玩家。

- 默认界面围绕“接下来做什么”组织任务。关键页面有明确的主要行动，但不强制统一固定布局。
- 推荐默认值，并解释推荐理由；首次安装不要求用户先理解 JVM 参数、下载线程、内存分配或 Maven 坐标。
- 使用渐进式高级选项。高级设置可搜索、可恢复默认，不让开启高级模式成为完成基本任务的前提。
- 明确“实例”是独立的一套游戏配置，包含版本、加载器、模组、配置及存档；首次出现用简短中文解释。展示当前选中的实例、账户和可启动状态，防止误操作。
- 文案尽量是“问题是什么、有什么影响、下一步怎么做”。技术详情和原始日志可以展开，不用模糊错误码代替解决路径。

### 4. 必须覆盖的产品能力

#### 4.1 游戏安装、运行环境与资源

- 原版及 Forge、NeoForge、Fabric、Quilt 的版本发现、兼容组合选择、自动下载安装。区分稳定版、快照、测试版；默认推荐稳定可用组合。显示不支持、元数据获取失败、组合冲突和暂无兼容版本的状态。
- 自动发现并按游戏版本、加载器要求、操作系统及处理器架构匹配 Java。缺失时给出可信来源的安装方案、许可说明与下载状态；支持手动选择路径、重新检测和失败回退。内存推荐不得超过可用资源，保留高级覆盖及风险提示。
- 下载游戏库、资源和所需运行组件；展示阶段、已完成量、总量是否已知、速度、校验、解压与安装完成状态。总量未知时用不确定进度，不伪造百分比。
- 校验文件完整性，损坏项可重试或重新下载。切换下载源须保留来源标识和完整性要求，不承诺任何来源永远可用。
- 实例隔离涵盖模组、配置、存档及日志；共享缓存与实例文件的区别清晰。创建、复制、重命名、迁移、打开目录及删除均说明影响，删除实例不得默认删除其他实例或共享资源。

#### 4.2 模组、资源平台与整合包

- Modrinth、CurseForge 的搜索、筛选、详情和合规安装，保留作者、项目、许可证、来源与跳转链接。展示游戏版本、加载器、客户端/服务端适用性及更新信息。
- 自动检查并解释必需依赖、可选依赖、版本范围、冲突和重复项。安装前展示变更计划；无法确定兼容时标注“未验证”，不宣称自动修复全部冲突。
- 禁止绕过平台鉴权、分发限制、作者下载限制或许可证。受限资源明确进入“待手动补齐”：展示原因、官方项目页、文件名及匹配条件；用户选入本地文件后校验身份和版本，错误文件给出修正路径，满足条件后继续。
- 更新模组前检查兼容性和依赖变化，允许选择性更新；涉及破坏性变更时先备份，提供可行的撤销或恢复方案。
- 支持整合包导入、安装、导出，至少设计 Modrinth `.mrpack` 和 CurseForge 清单式整合包路径。展示格式验证、版本/加载器识别、依赖解析、缺失/受限文件、覆盖文件冲突和许可证限制。
- 导出不默认打包账号凭据、访问令牌、日志隐私、个人服务器信息或存档。存档等私人内容需显式选择；不允许再分发的资源通过合法清单/链接表达或明确排除并说明，不伪装成可直接分发的完整包。

#### 4.3 账户、授权、皮肤与启动

- 微软正版账户使用外部系统浏览器完成官方 OAuth 授权；可设计设备码流程作为适用时的备选。启动器内不索要微软密码，不仿制官方登录页。交代浏览器跳转、等待、取消、超时、拒绝、回调失败、授权过期及重新授权。
- 明确区分“登录成功”“拥有 Minecraft Java 版资格”“可启动”。处理未拥有、资格无法验证、网络不可用及令牌失效；不得绕过游戏所有权或将离线模式作为未拥有者的替代购买路径。
- 离线启动仅适用于本地合法已有内容，并受已有授权和产品规则约束；说明不能下载缺失内容、不能重新在线验证、不能保证加入需要在线认证的服务器。区分“断网”“未登录”“无所有权”“缺少本地文件”，不可一律显示可离线启动。
- 账户管理包括添加、切换、移除、重新授权和隐私说明。移除账户说明本地凭据处理及对实例的影响，不默认删除游戏内容。
- 皮肤展示、选择或上传、模型类型及披风的可用能力按官方权限区分；区分本地预览、提交中与官方服务已确认生效，不能承诺任意皮肤/披风均可上传或全服生效。
- 启动流程包括就绪、检查、缺项修复、构建启动参数、启动中、游戏运行中、正常退出、启动失败、异常退出；提供日志入口、重复启动的明确规则和启动器窗口行为设置。

#### 4.4 数据保护、排错、个性化及服务器

- 存档与实例备份支持手动/自动策略、范围选择、进度、空间不足、失败、历史版本和恢复预览。恢复覆盖前说明范围并建议创建恢复前快照。游戏运行中存在文件一致性风险，应阻止不安全覆盖或引导先关闭游戏，不能声称任意时刻备份均一致。
- 崩溃排查将症状、日志证据、可能原因、置信程度和安全下一步分开；覆盖 Java 不匹配、内存不足、依赖缺失、模组冲突及未知原因。不要把猜测写成确诊。复制/导出/上传日志前预览并脱敏用户名、路径、服务器地址、令牌等；上传需要知情同意。
- 个性化包含浅色、深色、跟随系统，以及可选主题、背景、透明度、动态效果和字体缩放。自定义背景须有遮罩、对比度检查、安全回退和重置入口；减少动态效果、键盘焦点与警告可见性不可被主题关闭。
- 联网服务器列表支持添加、编辑、删除、收藏、刷新状态、复制地址及引导进入游戏连接；展示延迟、在线人数、游戏版本、不可达、未知及信息过期。服务器地址、版本等展示与连接前检查分开，不能把列表状态当成成功入服。
- 不假设已具备官方免费联机穿透、自动开服或任何无条件联机服务。若探索局域网、直连或第三方服务扩展，标明前提、提供方、费用/授权、隐私、安全和“待接入”状态；无服务时仍有清晰可用的服务器管理体验。

### 5. 下载、取消与恢复的真实边界

用任务模型贯穿安装、更新、导入及修复，设计排队、解析、下载、校验、解压、安装、待手动操作、暂停、失败、取消及完成。只有底层允许时才提供暂停/续传；取消、暂停和关闭窗口是不同动作。

必须具体呈现：断网后恢复、限流/服务不可用、无断点续传能力时重新下载、校验失败、磁盘不足、权限不足、目标文件被占用、应用中断后重新打开及受限资源待补齐。

- 每个阶段标明是否可立即取消、等待安全点取消或暂不可中断，避免一个“取消”按钮许诺所有阶段都能无损停止。
- 下载优先落到暂存区，提交前检查；取消清理未完成临时文件的规则明确，合法可复用缓存与用户原有内容不得误删。
- 区分新安装未提交、更新已提交、导入已有冲突文件三种情境。提交前可丢弃暂存变更；提交后只有存在备份或事务记录时才承诺恢复；外部文件变化、用户手动修改及已运行游戏的影响可能无法自动回滚。
- 失败后说明“已保留什么、会重新执行什么、哪些需要手动处理”。恢复旧版本、恢复存档及重试下载应各自有正确入口，不把重试称作回滚。

### 6. 设计范围与核心画板

先给出信息架构和任务流程，再绘制能覆盖以下任务的真实画板。允许合并承载相关功能，但不能用一个功能名列表代替设计。

3. 新建与安装：原版/加载器选择、版本兼容、Java 推荐、计划确认及安装任务详情。
4. 实例详情与管理：基础配置、模组、存档、备份、日志及高级设置的渐进式组织。
5. 资源发现与详情：双平台来源、筛选、依赖/冲突确认、受限资源手动补齐及更新计划。
6. 整合包导入/导出：格式检查、变更预览、限制说明和成功/失败结果。
7. 账户与皮肤：外部授权等待、异常、所有权状态、切换/移除及皮肤预览/提交状态。
8. 全局或上下文任务管理：进度、错误恢复、取消确认、取消后结果及无法回滚说明。
9. 备份与恢复：备份历史、范围、覆盖确认、运行中阻止和恢复结果。

12. 设置与个性化：主题、可读性保护、字体缩放、减少动态效果以及高级配置。

### 7. 状态、无障碍与适配

- 为适用页面提供正常、首次空白、筛选无结果、加载、部分成功、离线、权限受限、错误和重试状态。为可操作组件提供默认、悬停、按下、键盘焦点、禁用、加载、成功/错误反馈；禁用原因可被读取，不能只靠悬停解释。
- 危险操作确认应说明对象、范围和不可恢复部分，并提供退出路径；流程支持返回、取消、必要确认及保留输入。避免多层模态窗口与弹窗连锁。
- 使用真实长度中文、英文文件名、长路径和版本号，标注截断、换行、复制完整内容的规则。不要满屏占位文本或不可读的微小字。
- 文字满足 WCAG AA：普通文本对比度至少 4.5:1，大文本至少 3:1；关键控件边界和焦点可辨识。状态不只用颜色表达。说明键盘顺序、可见焦点、弹窗焦点约束与关闭后焦点返回。
- 关键页面至少交付 1024×720 与 1440×900 两种尺寸，覆盖浅深色验证；其余页面也须有明确适配规则。使用真实重排、伸缩、滚动及最小宽度策略，不用整张同比缩小代替适配。检查字体放大至 125% 和 150% 时主要任务是否仍可完成，必要时重排或滚动。
- 动效用于解释状态变化，提供减少动态效果版本；不依赖动画传递唯一信息。

### 8. Figma 原生交付约束

最终成果必须是 Figma Design 中可选中、修改文字、重排和替换组件的原生图层。按“探索、流程、设计系统、核心界面、状态、原型、交付说明”等职责组织页面；命名规则可自行优化。

- 使用原生 Frame、Text、Shape、Auto Layout，合理配置嵌套、间距、Hug/Fill、最小/最大宽度和约束。不要将整页截图、SVG 大图或扁平化图片作为可编辑稿。

### 9. 可点击原型的测试任务

用模拟数据验证并记录每项的起点、步骤、预期结果和恢复/退出路径；这些仅证明设计与原型覆盖，不证明真实功能实现。

1. 新用户不手动配置 Java，安装推荐原版并走到首次启动成功画板。
2. 创建 Fabric 实例，安装有依赖的模组，再处理一次不兼容版本；检查 Forge、NeoForge、Quilt 的选择与不支持状态。
3. 从 Modrinth 安装资源；导入含 CurseForge 受限文件的整合包，经官方页面引导、错误文件校验、正确文件补齐后继续。
4. 安装过程中断网、恢复，再遭遇校验失败；分别展示可续传与必须重新下载的处理。
5. 在下载阶段取消；在安装提交阶段请求取消；分别确认临时文件、缓存、旧实例和已提交内容的最终状态。
6. 微软外部授权经历取消/超时后重试，处理无所有权、资格待验证、凭据过期，并完成合法离线条件判断。
7. 切换账户与皮肤，区分本地预览、提交失败和服务确认生效。
8. 导入已有实例发生文件冲突，预览并选择安全方案；导出时排除凭据和受限再分发资源。
9. 游戏运行中尝试恢复存档被安全阻止；关闭游戏后创建恢复前快照并恢复指定备份。
10. 异常退出后理解可能原因，展开证据，预览脱敏日志后决定是否分享。
11. 添加服务器，处理版本不一致、不可达与未知状态，不把“添加成功”或列表在线伪装成入服成功。
12. 在两种窗口尺寸及浅深色中完成主要任务；高干扰背景及字体放大后仍能识别主要行动、错误和键盘焦点。

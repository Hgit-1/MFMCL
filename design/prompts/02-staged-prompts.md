# Minecraft Java 启动器：分阶段设计提示词

适用于逐轮推进、逐轮检查的设计会话。先发送“每轮共同约束”，再依次发送四个阶段；同一会话可与 `01-master-prompt.md` 配合。若新开会话，附上已有设计文档、选型结论和前阶段产物，不要让 AI 猜测历史决定。阶段产物是设计要求，不代表软件功能已实现。

## 每轮共同约束

你正在从零独立设计一款中文 Minecraft Java 桌面启动器，初心者能以推荐默认值完成安装与启动，熟练用户通过渐进式高级选项获得控制权。成熟度目标达到或超越 PCL2，但未经完整对标，不能宣布已实现这一目标。

严禁读取、索引、检索、截图、运行或间接访问 `/home/mdfz31/MFMCL/PCL`，不要参考 PCL/PCL2 的界面、代码、布局、素材和截图。不做外部调研，以明确需求及透明假设独立设计。品牌、主色、导航形式和布局均由设计论证决定，不预先固定。

始终保留以下需求：

- 原版及 Forge/NeoForge/Fabric/Quilt 自动下载安装、兼容组合选择、Java 自动匹配和手动覆盖、资源完整性校验、实例隔离。
- Modrinth/CurseForge 合规搜索和安装、依赖兼容与更新检查；受限资源从官方项目页引导用户手动补齐并校验，不能绕过平台限制；整合包导入/导出含格式校验、冲突及再分发许可边界。
- 微软正版外部官方授权，不索要密码，不复刻登录页，不绕过所有权。登录、资格验证和可启动是不同状态；离线仅允许本地合法已有内容并受已有授权约束，不是绕过购买或下载缺失资源的入口。
- 账户切换/移除/重新授权与皮肤预览/提交状态、启动全过程、游戏运行与退出、备份恢复、崩溃证据与隐私脱敏。
- 个性化同时保护可读性、键盘焦点和减少动态效果；联网服务器列表不等于已具备官方免费联机穿透、开服或入服能力。
- 下载失败恢复、暂停/取消的支持条件、暂存与提交的区别、缓存/用户数据的保留规则，以及只有存在备份或事务记录时才能承诺的回滚边界。

交付目标是原生可编辑 Figma Design：文字和图形可分别修改，Auto Layout、组件/变体/属性、Variables、浅深色、至少 1024×720 和 1440×900 适配及完整状态、可点击原型。Figma Make 网页预览、代码、截图或改后缀文件不能冒充原生稿或 `.fig`。只有真实支持导出的工具成功导出后才称为 `.fig`；无原生写入能力时明确未交付，提供规格也不能谎称设计稿完成。所有系统能力均以模拟原型表达，不真实采集凭据或执行系统操作。

每轮用中文、普通标题和列表输出，不使用表格。清楚区分已设计、已在原型验证、尚待验证、依赖真实系统接入四种结论。

## 阶段一：探索方向与产品结构

### 可复制提示词

请依据共同约束完成第一阶段，只做独立概念探索、信息架构与关键低保真，不急于绘制全部高保真。

1. 用简短场景说明两类用户：不懂 Java/加载器的新用户，以及管理多个模组实例的熟练用户。列出他们最重要的任务、易误解的术语及安全风险。
2. 提出三个实质不同的设计方向，分别说明信息组织、主要行动、视觉原则、导航与布局假设、初次启动路线及复杂功能扩展方式。至少给出各自的首次使用和日常启动低保真草图，避免同一结构换皮。
3. 根据首次成功率、认知负担、状态清晰度、扩展性、可读性及工程合理性，自选一个方向并解释取舍。不要要求用户替你决定所有细节，也不要固定品牌、主色或导航后再倒推理由。
4. 输出选定方向的信息架构、全局/实例/账户范围划分、主要对象及关系。解释实例与共享缓存的区别，保证不会在错误实例中安装模组、恢复存档或启动游戏。
5. 定义推荐默认值及理由：游戏版本、兼容加载器、Java、内存、安装目录、备份策略、启动器窗口行为。未知政策或版本支持只标注待验证，不发明接口。
6. 列出后续核心画板：首次引导、日常启动、安装、实例管理、资源发现与依赖、整合包、账户/皮肤、任务管理、备份恢复、启动/诊断、服务器、设置/个性化。注明各自主要行动与进入/返回方式，不强制一项一页。
7. 列出高级功能如何逐步展开，以及新用户完成首次安装前无需回答的设置。提供实际中文示例，不用术语解释堆满首页。
8. 说明当前是否真正能够创建 Figma Design 原生内容、交付文档链接及导出 `.fig`；只有实际工具能力才能作为交付承诺。权限不足时如实列出阻碍。

本阶段交付三个方向、选型理由、信息架构、推荐默认值与关键低保真。自查功能是否都有合理归属、主要任务能否被发现，再进入交互阶段。

## 阶段二：流程、状态与可点击低保真原型

### 可复制提示词

请沿用第一阶段选定方向，完成交互流程与状态设计。必要时修正信息结构并解释原因，不悄悄更换整套导航。

请用流程图或分支列表，加上真实原生低保真画板，覆盖以下任务：

1. 首次使用 → 目录与环境检测 → 推荐原版/Java → 安装计划 → 下载/校验/提交 → 可启动。支持 Java 缺失、架构不匹配、手动路径无效、磁盘不足和权限不足。
2. 新建 Forge、NeoForge、Fabric、Quilt 实例 → 兼容版本筛选 → 依赖组合确认。重点完整连通一条 Fabric 模组安装流程，同时分别画出其他加载器选择与不支持状态；不能只写加载器名称就算覆盖。
3. 从 Modrinth/CurseForge 发现资源 → 详情与来源/许可 → 必需/可选依赖 → 冲突检查 → 变更计划 → 安装。检查客户端/服务端差异、重复项及未知兼容状态。
4. 整合包导入 → 格式与清单校验 → 覆盖冲突 → 受限资源待补齐 → 官方项目页引导 → 本地选入/身份与版本校验 → 继续。覆盖错误文件和取消补齐；导出默认排除凭据、隐私日志和私人存档，受限再分发资源只通过允许的清单/链接表达或排除并说明。
5. 微软外部系统浏览器授权 → 等待 → 成功/取消/超时/拒绝/回调失败 → 所有权验证。区分无资格、无法联网验证及凭据过期；离线判断依据本地内容与合法已有授权，不把无所有权引向离线绕过。
6. 账户切换、移除、重新授权，以及皮肤本地预览、提交中、失败与官方确认生效；披风与在线修改按实际权限标注可用性。
7. 启动检查 → 缺项修复 → 启动中 → 运行中 → 正常/异常退出。明确重复启动规则、日志入口及启动器关闭行为；启动成功不等于入服成功。
8. 手动/自动备份 → 范围与空间确认 → 备份结果 → 历史恢复预览 → 运行中安全阻止 → 关闭游戏 → 恢复前快照 → 覆盖确认 → 恢复结果。不要承诺运行中的文件始终一致。
9. 异常退出 → 症状和日志证据 → 带置信程度的可能原因 → 安全建议 → 脱敏预览 → 用户同意后分享。包含无法诊断状态，不将猜测写成确诊。
10. 添加/编辑/收藏/刷新服务器 → 在线/不可达/未知/状态过期 → 版本提示 → 启动游戏连接引导。明确直连、局域网或第三方服务各自前提；没有已接入的联机服务就不展示虚假“免费穿透已开通”。
11. 主题、背景及字体缩放预览 → 对比度保护/遮罩 → 保存或恢复默认；减少动态效果独立可达。

为任务管理另画一组可追踪的状态分支：排队、解析、下载、校验、解压、安装、待手动操作、可暂停/不可暂停、失败、取消请求、已取消、已完成。总量未知时使用不确定进度。

必须明确以下边界：

- 断网、限流、服务故障、校验失败、文件占用和应用中断后的恢复行为。支持断点续传才显示续传，否则解释重新下载范围。
- 下载阶段可取消；校验/解压/提交阶段按能力立即取消或等待安全点。说明取消过程中按钮状态、关闭窗口的后果和最终结果。
- 新安装提交前丢弃暂存、更新提交后恢复备份、导入中用户原有文件冲突分别设计。记录临时文件、共享缓存、旧实例和用户数据的处理；无法恢复的外部变更明确说明。
- 可恢复失败优先给出安全的下一步；重试、修复、撤销和恢复备份不能混为一个动作。

画板应覆盖正常、空白、无结果、加载、离线、部分成功、权限受限、错误及重试。危险操作有范围和退出路径；返回不丢无须丢弃的输入；外部网页、文件选择、授权和游戏启动用注明“模拟”的画板承接。

连接可点击低保真原型，标出起点、主要路径和错误分支。说明键盘顺序、弹窗焦点约束/返回、非颜色反馈及禁用原因。每条路径走查成功与失败后恢复两种结果；修复断链后再进入组件与高保真。

## 阶段三：原生组件、变量与高保真界面

### 可复制提示词

请在第二阶段验证后的结构上建立设计系统与高保真界面，保持独立视觉表达，不套用现成启动器界面。

1. 明确品牌与视觉选择及其与任务的关系。不要为了“Minecraft 感”牺牲中文可读性；主色、字体、间距、圆角和层级由选定方向推导。
2. 在 Figma Design 中创建原生 Frame/Text/Shape 和 Auto Layout。合理使用嵌套、Hug/Fill、约束、最小/最大宽度与滚动规则。长列表可以使用示例数据，但不能整屏栅格化或将整页 SVG 当作可编辑布局。
3. 创建语义化 Figma Variables：文字、表面、边界、焦点、成功/警告/错误、遮罩等颜色，以及适用的间距和尺寸变量；建立浅深色模式。排版、效果等用合适样式管理，避免所有值逐页手填。
4. 创建组件和变体：按钮/图标按钮、输入/选择/搜索、复选与切换、版本及实例选择、资源条目、依赖与冲突、账户与授权状态、任务与进度、警告/错误/结果、弹窗与危险操作确认。按职责决定具体呈现，不强制全部使用卡片。
5. 组件包含默认、悬停、按下、焦点、禁用、加载及适用的成功/错误状态；使用属性、实例替换和变体表达内容与状态，不大量复制脱离组件的控件。明确哪些组件允许覆写，避免变体组合无意义膨胀。
6. 将核心任务转为高保真：首次引导、日常启动、安装、实例/模组、资源及受限文件、整合包、账户/皮肤、任务/取消、备份恢复、启动/排错、服务器和设置。第二阶段的错误及危险操作分支不得在美化时消失。
7. 至少为首次使用、日常启动、安装/任务、实例/资源管理、备份恢复、诊断和设置交付 1024×720 与 1440×900 两档；其余核心界面提供能实际应用的适配规则并抽查。两档均检查浅深色，窄窗口通过重排、收敛次要信息和滚动适配，不缩成微小字。
8. 普通文本对比度至少 4.5:1，大文本至少 3:1；关键控件、边界及焦点可辨识。错误、选中和在线状态都有文字或图形辅助。测试长中文、英文路径、版本号、125%/150% 字体缩放与键盘使用，解释无法在静态稿实测的部分。
9. 个性化设计提供背景遮罩、透明度范围、对比度警示/自动保护、安全回退和一键重置；高干扰背景不能遮挡主要行动、错误或焦点。提供减少动态效果版本。
10. 将高保真组件接入原型，保留起点、返回、取消、错误恢复及模拟外部操作。补充合理动效与反馈，避免用动效掩盖状态或以自动跳转代替真实点击路径。

交付实际可编辑 Design 文档、组件/变量位置、双尺寸浅深色画板及原型入口。Figma Make 代码或网页演示可作补充但不算原生交付；没有工具支持真实导出时明确没有 `.fig`，不要伪造链接或文件。

## 阶段四：任务走查、修正与交付完善

### 可复制提示词

请对现有原生设计稿做最后一轮任务走查和修正，使用 `03-acceptance-prompt.md` 的验收要求进行完整检查。先处理安全与流程问题，再处理视觉细节；发现问题后直接修正可修正项，而非只写建议。

至少完成以下十二项模拟测试，逐项记录起点、操作、预期、实际观察及修复/复测状态：

1. 初心者使用推荐配置自动匹配 Java，安装原版并进入首次启动成功状态。
2. 创建 Fabric 实例，安装必需依赖，处理不兼容模组；验证其他三类加载器的选择及不支持分支。
3. Modrinth 合规安装与 CurseForge 受限资源官方引导、错误文件拒绝、正确文件补齐。
4. 导入整合包并解决覆盖冲突；导出不泄露凭据、不默认带出私人内容、不违规再分发资源。
5. 断网恢复、可续传与不能续传两种情况、校验失败重试、磁盘不足或文件占用。
6. 下载取消、提交阶段请求取消、应用中断后恢复；核对暂存、缓存、旧实例、用户文件及无法自动回滚的说明。
7. 微软外部授权取消/超时后重试、所有权不存在/无法验证、凭据过期及合法离线条件。
8. 账户切换与移除、皮肤预览/提交/失败/确认生效。
9. 游戏运行中阻止不安全恢复，关闭后创建恢复前快照并恢复指定存档。
10. 异常退出排查、证据与推测区分、脱敏预览及分享知情同意。
11. 添加服务器、版本不一致、不可达和未知状态；列表与实际入服清晰区分，没有虚假穿透承诺。
12. 两档尺寸、浅深色、高干扰背景、字体放大和键盘焦点下仍能完成主要任务。

同时检查：主要按钮不是死链接；成功/错误分支能返回；状态文案与可执行动作一致；危险操作正确说明对象范围；高级选项渐进展示；原生文字、Auto Layout、组件实例、变体和 Variables 可真实编辑。
